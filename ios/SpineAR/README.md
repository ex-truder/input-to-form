# Spine AR — native iOS prototype

Прототип для проверки непрерывного PBR-блендинга позвоночника на iPhone.
**На Windows исходники подготовлены, но Xcode-сборка и запуск на iOS не проверены.**
Это обычное iOS-приложение. App Clip target, сервер активации, associated domains,
подпись и распространение в эту версию не входят.

## Что реализовано в исходниках

- ARKit: поиск горизонтальной поверхности, размещение по нажатию, поворот и масштаб.
- RealityKit: анимация формы из HQ USDZ, работа с импортированными анимациями всех частей.
- Metal `CustomMaterial`: непрерывное смешивание albedo, normal и ORM из двух состояний.
- Один таймер для геометрии и материалов. Кости и диски следуют своим keyframes
  из существующего `model-animation.json`, с проходом вперёд и назад.
- Пауза, перемотка, повторное размещение; ошибки камеры, ресурсов, материалов и анимации.
- Текстуры читаются из исходных KTX2 без уменьшения: albedo/ORM 2K, normal 1K.
- Цвет смешивается в линейном пространстве, normal — с нормализацией;
  metallic остаётся 0, как в исходных материалах.

Каждый материал использует один raw-атлас 4096×5120. В нём шесть исходных карт
без апскейла: from/to albedo, ORM, normal. Шейдер использует точные области
атласа и линейную фильтрацию без mip-смешивания областей. Потребление памяти
и частоту кадров нужно измерить на iPhone 13 Pro; это пока не оптимизированный
производственный просмотрщик.

## Открыть на Mac

1. Распаковать `artifacts/SpineAR-iOS-prototype.zip`. Внутри уже есть ресурсы:
   на Mac не нужны Blender, Python, Node или генератор проекта.
2. Открыть `SpineAR/SpineAR.xcodeproj` в Xcode 15 или новее.
3. В Signing & Capabilities выбрать свою Team. При необходимости изменить
   bundle identifier `pro.kustart.spinearprototype` на уникальный.
4. Подключить iPhone с iOS 17 или новее, выбрать его как устройство запуска,
   включить Developer Mode на телефоне, если Xcode этого требует.
5. Нажать Run. Разрешить камеру. Найти поверхность и коснуться её.

После настройки подписи сборку можно проверить командой:

```bash
xcodebuild -project SpineAR.xcodeproj -scheme SpineAR -configuration Debug \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
```

Если компилятор сообщает об ошибке Swift/Metal или SDK, сохранить полный текст
ошибки: проверка структуры проекта на Windows не равна компиляции Xcode.

## Проверка эффекта

1. После размещения наблюдать полный цикл (~8,67 секунды): деформация и текстуры
   должны меняться вместе. Сначала меняется диск, позже — фактура кости.
2. Поставить на паузу, перемотать на 0%, 50% и 100%. Все части должны оставаться
   в одной стадии; цвета не должны становиться металлическими.
3. Осмотреть UV-швы, направление normal map, мелкую фактуру и прозрачные внутренности
   диска. Последние сохраняют исходный материал и не заменяются шейдером блендинга.
4. Проверить перемещение приложения в фон, возврат и повторное размещение.
5. Проверить память, нагрев и FPS в Xcode на iPhone 13 Pro.

При несовпадении импортированных имён материалов используется таблица имён
мешей/узлов, полученная из GLB. Если не найдены обе группы (кость и диск),
просмотрщик сообщает об ошибке. В консоли Xcode выводятся количества привязок
материалов и ресурсов анимации.

## Пересобрать пакет из репозитория

Из корня проекта, после сборки HQ USDZ согласно `docs/lab-ar.md`:

```powershell
node tools/ar/decode-spine-textures.cjs
python tools/ar/prepare-ios-prototype.py
```

Скрипт проверяет каждый пиксель упакованных областей против исходных карт,
ссылки объектов Xcode-проекта, Info.plist, XML scheme и целостность ZIP.
`Generated/` исключён из Git; готовый ZIP содержит эту папку целиком.

## Дальнейший App Clip

После успешной проверки шейдера на устройстве можно выделить общий просмотрщик
для полного приложения и App Clip target. Для запуска из Safari понадобятся
Apple Developer Team, идентификатор App Clip, его подпись, HTTPS URL активации
и associated domains. Способ доставки моделей и ограничения размера нужно
проверять для выбранной версии iOS. В текущем пакете нет обещания готового App Clip.
