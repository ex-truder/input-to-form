# Экспорт параметров Houdini для демонстраций HDA

Экспортёр читает выбранные ноды и создаёт описание параметров и их вычисленные
состояния по кадрам. Подходит для одной или нескольких нод; тип HDA и имена полей
заранее знать не нужно. Сторонние Python-пакеты не требуются.

## Быстрый запуск в Houdini

Выдели нужные ноды. Открой **Windows → Python Shell** и выполни:

```python
import runpy

exporter = runpy.run_path(
    r"D:\YandexDisk\XYZ\INPUT-TO-FORM SITE\tools\houdini\hda_export.py"
)

result = exporter["export_selected"](
    output_dir=r"D:\YandexDisk\XYZ\INPUT-TO-FORM SITE\houdini-exports.local",
    name="demo",
    start_frame=1,
    end_frame=120,
    sample_step=1,
)
```

Укажи свой диапазон кадров. Начальный и конечный кадры включены. Папка создаётся
автоматически. Без `start_frame` и `end_frame` используется playback range сцены.
Сначала лучше проверить небольшой диапазон, например 10–20 кадров.

Для повторной выгрузки с тем же именем добавь `overwrite=True`. По умолчанию
существующие файлы защищены от перезаписи.

Чтобы не зависеть от выделения:

```python
result = exporter["export_nodes"](
    output_dir=r"D:\YandexDisk\XYZ\INPUT-TO-FORM SITE\houdini-exports.local",
    nodes=["/obj/geo1/my_hda", "/obj/geo1/another_node"],
    name="two-nodes",
    start_frame=1001,
    end_frame=1100,
)
```

## Кнопка на полке

Создай Shelf Tool, выбери язык **Python**, вставь:

```python
import runpy
runpy.run_path(
    r"D:\YandexDisk\XYZ\INPUT-TO-FORM SITE\tools\houdini\export_selected.py",
    run_name="__main__",
)
```

Кнопка предлагает выбрать папку, имя экспорта, диапазон и шаг. Она не заменяет
существующие файлы: выбери новое имя или используй Python Shell с
`overwrite=True`.

## Результат

```text
demo.parameters.json   Описания, исходные состояния, варианты структуры
demo.animation.json    Временная шкала и дорожки изменения состояний
demo.report.json       Отчёт о полноте и ошибках
```

В Python Shell выводятся пути, количество нод/сэмплов/дорожек и статус:

- `ok`: выгрузка завершена без зарегистрированных ошибок и предупреждений.
- `partial`: файлы созданы, но есть неподдерживаемые типы, ошибки вычисления
  или недоступные исходные данные. Подробности находятся в `issues` отчёта.

Неисправное поле получает состояние `error`; неподдерживаемое — `unsupported`.
Предыдущее успешное значение не подставляется вместо ошибки. Повторяющиеся
проблемы объединяются с количеством повторений и первым/последним кадром.
Кнопки представлены с состоянием `no_value`: история их нажатий не выгружается.

Три файла связаны `exportId`. При новой выгрузке переноси комплект целиком.
Каждый файл сначала подготавливается во временном файле. Комплект из трёх
файлов не является одной файловой транзакцией: прерывание записи системой
может оставить неполный комплект, поэтому проверка `exportId` обязательна.

## Какие данные сохраняются

- Все доступные через `parmTuples()` параметры выбранных нод, включая скрытые,
  значения по умолчанию и параметры без ключей. Внутренние сети HDA рекурсивно
  не обходятся; внутреннюю ноду можно передать отдельно.
- Числа, векторы, RGB/RGBA, чекбоксы, строки, файловые пути, меню.
- Для строк сохраняется вычисленный текст; исходный текст с `$F`, `$HIP` и
  другими выражениями хранится отдельно, когда API позволяет его прочитать.
- Для меню — вычисленное значение и текущие списки токенов/подписей. Значение
  целочисленного меню не обязательно равно индексу; его трактовку определяют
  метаданные шаблона, включая `menuUseToken`.
- Числовые и цветовые рампы: точки, значения, интерполяция, цветовой режим
  при доступности, вычисленный профиль для рисования в браузере.
- Папки, вложенные шаблоны, повторяющиеся блоки multiparm, индексы экземпляров
  и ссылки на родительский блок. Служебные компоненты рамп также сохраняются;
  на сайте их можно скрыть по `parentMultiparm` и типу родительского параметра.
- Состояния скрытия, блокировки и отключения отдельных компонентов по времени.
- Доступные метаданные шаблонов: подписи, диапазоны, defaults, теги, help,
  условия интерфейса, callback/menu scripts и другое. Исходное описание
  шаблона дополнительно сохраняется как `houdiniPythonSource`.
- Исходные ключи через HOM `asJSON()`, выражения и экстраполяция каналов.
  Они служат архивными данными; воспроизведение опирается на вычисленные сэмплы.

`houdiniPythonSource` и скрипты из метаданных — текст. Браузерный проигрыватель
не должен выполнять этот код. Опция `include_source=False` отключает только
дополнительный Python-текст шаблонов; прочие метаданные сохраняются.

Произвольные `Data`-параметры с геометрией/изображениями/бинарными объектами
помечаются как `unsupported`. Это не резервная копия HDA или HIP. Геометрия,
внешние файлы и содержимое текстур не вкладываются в JSON.

## Как хранится время

Houdini последовательно переводится на каждый кадр диапазона; затем читаются
значения, меню, состояния интерфейса и актуальный состав полей. Проверяются
все поля, поэтому зависимости через выражения не отбрасываются из-за отсутствия
собственных ключей.

В `animation.json` есть:

```json
{
  "sampleFrames": [1001, 1002, 1003],
  "sampleTimes": [0, 0.041666666666666664, 0.08333333333333333]
}
```

Это пример для 24 FPS. `sampleTimes` измеряется в секундах относительно первого
сэмпла: `(frame - startFrame) / fps`. Абсолютное время Houdini для привязки
ролика не используется.

Дорожка содержит пары `[sampleIndex, state]`. Если полное состояние поля не
меняется, новые пары не записываются. Изменение скрытия или списка меню тоже
считается изменением состояния.

```json
{
  "interpolation": "hold",
  "samples": [
    [0, {"status": "ok", "value": 1, "components": []}],
    [12, {"status": "ok", "value": 2, "components": []}]
  ]
}
```

Чтение выполняется поиском последней записи с индексом не больше текущего.
После последнего сэмпла значение удерживается; никаких предположений о
длительности последнего кадра видео экспортёр не делает. `lastSampleTime` —
время последнего сэмпла, а не длительность видеофайла.

`sample_step=0.5` позволяет снимать значения на субкадрах. Если конец диапазона
не кратен шагу, он всё равно добавляется последним сэмплом. При шаге больше
одного кадра изменения между сэмплами могут быть пропущены. Изменения параметров
вручную во время просмотра не записываются как события: выгружается состояние
сцены, которое можно вычислить на её временной шкале.

Состав активных полей определяется через `layoutTracks`: набор параметров может
меняться, например у multiparm. Нельзя выводить сразу все накопленные дорожки:
сначала нужно выбрать layout для текущего времени, затем его `activeDefinitions`.
В модуле есть эталонная функция `state_at_sample(parameters, animation, index)`.

Структура `parameters.json`:

- `nodes`: исходные пути/типы нод, `initialLayoutId`, `initialStates`.
- `templates`: описания типов полей и папок; `children` ссылается на шаблоны.
- `definitions`: описания конкретных экземпляров полей, ссылки `templateId`,
  имена компонентов, расположение и исходные каналы.
- `layouts`: набор корневых шаблонов и активных экземпляров для каждой
  наблюдавшейся структуры ноды.

Идентификатор ноды зависит от её пути и сохраняется при изменении порядка
выделения. Переименование/перемещение ноды меняет идентификатор. Индексы
multiparm обозначают позиции экземпляров, а не постоянные идентификаторы
объектов после вставки или перестановки.

Числа `NaN`, `Infinity`, `-Infinity` представлены явными объектами вроде
`{"$number":"NaN"}`, чтобы файлы оставались стандартным JSON.

## Профили рамп и цвета

По умолчанию рампа дополнительно вычисляется в 64 точках через `hou.Ramp.lookup`.
Профиль аппроксимирует внешний вид кривой; оригинальные точки и basis остаются
в файле. Для большей детализации используй `ramp_resolution=128` или `256`.
Чтобы отключить профиль и уменьшить файл — `ramp_resolution=0`.

Цвета сохраняются в исходном виде параметров. Преобразование OCIO, view transform
и перевод в CSS/sRGB здесь не выполняются. Настройка отображения относится к
следующему этапу разработки веб-компонента.

## Воздействие на сцену

Экспортёр не записывает HIP, не устанавливает значения параметров и не меняет
ключи. Он временно меняет текущий кадр и обновляет состояния интерфейса.
Исходный кадр восстанавливается через `finally`, в том числе после ошибки или Esc.

Вычисление выражений и динамических меню может запускать код самой сцены и
вызывать cook зависимостей. Для параметров, зависящих от симуляции, данные нужно
подготовить/закэшировать так же, как для рендера видео. Экспорт с середины
диапазона не выполняет автоматически preroll симуляции.

Не редактируй ноды во время выгрузки. При Esc или фатальной ошибке чтения сцены
готовые файлы не записываются; поэлементные ошибки вычисления дают `partial`.
Принудительное завершение процесса не позволяет гарантировать восстановление
кадра. Полная проверка структуры на каждом сэмпле увеличивает время экспорта
больших интерфейсов; эта версия ориентирована на полноту захвата.

## Проверки

Самопроверка в Houdini создаёт отдельную временную ноду с разными полями,
анимацией, выражениями, двумя рампами и multiparm, выгружает её и проверяет
значения. После проверки нода удаляется; файлы результата остаются:

```python
exporter["self_test"](
    output_dir=r"D:\YandexDisk\XYZ\INPUT-TO-FORM SITE\houdini-self-test.local",
    overwrite=True,
)
```

При успехе в Shell будет `HDA exporter self-test PASSED`. Чтобы оставить
тестовую ноду для осмотра, передай `keep_node=True`.

Проверки формата, разреженных дорожек, изменения состава multiparm, ошибок,
отмены, восстановления кадра, нескольких нод и записи файлов запускаются
обычным Python с подставным HOM:

```powershell
python -m unittest discover -s tools/houdini -p test_hda_export.py -v
```

Эти тесты сами по себе не подтверждают совместимость с настоящим Houdini.

Запуск через `hython`:

```powershell
& 'C:\Program Files\Side Effects Software\Houdini 22.0.429\bin\hython.exe' `
  tools/houdini/hda_export.py --self-test --output tools/houdini/self-test.local --overwrite
```

Для отдельного процесса с HIP:

```powershell
hython tools/houdini/hda_export.py --hip D:/scenes/demo.hip `
  --nodes /obj/geo1/my_hda --output D:/exports/demo --start 1 --end 120
```

`--hip` запрещён в графическом Houdini, чтобы случайно не заменить открытую
сцену. Все аргументы: `hython tools/houdini/hda_export.py --help`.

Для первого теста на твоей HDA нужны получившиеся JSON и, при ошибках, текст
traceback из Python Shell. Передавать исходный проект для этого не требуется.
